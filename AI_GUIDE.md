# AI_GUIDE.md — правила для ИИ-ассистентов в проекте ForzaDJ (сайт)

> **Это первый файл, который ты (ИИ) обязан прочитать.** Второй — `PROJECT_HANDOFF.md`.
> Читай оба **до** любого изменения. Не начинай писать код, пока не сверился с ними.
> Файл рассчитан на любых ассистентов: Gemini, GPT/Codex, Kimi и т.д.

Как человек подключает этот файл — см. раздел «Шаблон промта» внизу.

---

## 0. Три правила, нарушение которых ломало проект (реальные случаи)

1. **Любая ESLint-ошибка ВАЛИТ прод.** `next build` падает на ошибках линтера
   (`prefer-const`, `no-unused-vars` и т.п.). Упавшая сборка = нет `.next` =
   сайт уходит в 502-краш-луп. **Перед тем как сказать «готово», запусти
   `npx tsc --noEmit` И `npx eslint <изменённые файлы>`.** Оба должны быть чистыми.
   Пример реальной поломки: `let buffer`/`let meta`, которые не переприсваиваются
   → `prefer-const` → прод лежал.

2. **Каждый push в `main` = деплой с даунтаймом.** CI (GitHub Actions → SSH)
   делает `git reset --hard`, `npm install`, **`pm2 stop` → `next build` →
   `pm2 start`**. На время сборки сайт НЕДОСТУПЕН (так сделано намеренно: VPS
   3.8 ГБ RAM не тянет живой процесс + сборку). Поэтому: **не пуши мусорные/
   промежуточные коммиты в main**, собирай изменения в один осмысленный коммит.
   Не пушь, если не уверен, что сборка пройдёт (см. правило 1).

3. **Всегда обновляй документацию в том же изменении.** README.md +
   PROJECT_HANDOFF.md (профильный раздел + таблица «Последние изменения» с
   хэшем и датой). Это требование владельца, не опция.

## 1. Как ты должен работать (процесс)

- **Read-first.** Прочитай `PROJECT_HANDOFF.md` целиком (или нужные разделы) и
  этот файл. Проект уже большой — почти всё уже решено, не изобретай заново.
- **Проверяй, прежде чем править.** Файл/функция/флаг, на которые ты
  ссылаешься, ДОЛЖНЫ существовать — открой и убедись. Не выдумывай API,
  импорты, поля БД, названия компонентов. Если не нашёл — значит, этого нет.
- **Маленькими шагами.** Одна задача — один коммит. Не меняй несвязанный код,
  именование и структуру «заодно».
- **Повторяй существующие паттерны** репозитория, а не вводи новые.
- **Не уверен — спроси**, а не угадывай. Лучше один вопрос, чем сломанный прод.
- **Не ставь заглушки/`TODO позже`** в коде, который идёт в main. Только
  рабочий код.
- **Перед «готово» — чек-лист** (см. раздел 4).

## 2. Архитектурные факты, которые часто понимают неправильно

- **Стек:** Next.js 15 (App Router, Server Components, **Turbopack**), TypeScript,
  Tailwind v4 + shadcn/ui, Prisma → **локальный PostgreSQL 16 на VPS** (НЕ Supabase
  для данных — перенесено по 152-ФЗ; Supabase остался только для Storage и выпуска
  сессий). Деплой: VPS + PM2, CI через GitHub Actions.
- **Группы маршрутов:** `(public)` гость/лендинг, `(dj)` зона диджея (нужна
  сессия), `(shared)` публичные паки/крейты, `(studio)` админка (ADMIN+).
  Клади фичу в свой слой, не размазывай.
- **Слои сервера:** `auth/`, `repositories/` (Prisma + soft-delete фильтр),
  `services/`, `storage/`, `actions/` (Server Actions, каждый повторно
  проверяет права + zod), `jobs/` (inline-очередь), `events/`. Не обращайся к
  Prisma напрямую из компонентов — только через репозитории/сервисы.
- **Soft delete везде** (`deletedAt`). Не делай hard delete. UUID v7 — id,
  `slug` — публичный идентификатор в URL.
- **Auth только Telegram.** Вход на проде идёт через **long-polling**
  (`scripts/tg-poll.mjs`, PM2 `tg-poll`), НЕ через webhook — Timeweb блокирует
  входящие с IP Telegram. Не «чини» это на webhook.
- **Аудио-пайплайн:** загрузка → `asset.process` (метаданные, превью, waveform,
  извлечение/вшивание обложки) → `audio.analyze` (BPM/Key через essentia.js WASM,
  **только Node-runtime, не Edge**). Анализ не блокирует публикацию и заполняет
  только пустые поля (ручная правка приоритетнее).
- **Брендовые обложки по жанру:** единая функция `embedArtworkIntoAudio` в
  `src/server/services/branded-artwork.ts` — общая для сайта и ботов. НЕ дублируй
  её, НЕ делай второй вариант.
- **Публикация от ботов:** один эндпоинт `POST /api/bot/upload` (auth
  `x-bot-secret` = `BOT_UPLOAD_SECRET`). И бот публикации, и бот модерации ходят
  сюда. Логику публикации НЕ дублируй в других местах.
- **Загрузки идут через Server Actions**, поэтому лимит тела поднят в
  `next.config.ts` (`serverActions.bodySizeLimit`). Дефолтный 1 МБ роняет аудио.

## 3. Грабли деплоя и окружения

- Сайт крутится под PM2 как `forzadj` (`bash -c npm run start` → `next start`).
- `.next` — продакшн-сборка; без неё `next start` крашится в цикле. Если правил
  что-то, влияющее на сборку — убедись, что build проходит.
- Не коммить два lock-файла одновременно (`package-lock.json` + `pnpm-lock.yaml`)
  без нужды — это ломает автодетект пакетного менеджера в некоторых окружениях.
- Секреты — только в env (`/opt/forzadj/.env` на сервере), НИКОГДА в коде,
  в `NEXT_PUBLIC_*` или в git. Не логируй токены.
- БД — локальный Postgres (`127.0.0.1:5432`). При смене `.env` PM2 нужно
  **пересоздать** (`pm2 delete` + `start`), `--update-env` не всегда подхватывает.

## 4. Чек-лист перед словом «готово»

- [ ] `npx tsc --noEmit` — чисто.
- [ ] `npx eslint <изменённые файлы>` — чисто (иначе прод не соберётся).
- [ ] Изменение соответствует существующим паттернам, не ломает несвязанное.
- [ ] Обновлены README.md и PROJECT_HANDOFF.md (раздел + changelog с хэшем/датой).
- [ ] Все ссылки на файлы/функции/поля проверены — они существуют.
- [ ] Коммит осмысленный, один concern; готов к деплою (сборка пройдёт).
- [ ] Секреты не попали в код/доки/логи.

```
Ты работаешь в проекте ForzaDJ. ПЕРЕД любым действием прочитай два файла и
строго им следуй:
1) AI_GUIDE.md  (правила и типовые грабли)
2) PROJECT_HANDOFF.md  (архитектура и текущее состояние)

Правила: не выдумывай файлы/API/поля — проверяй, что они существуют; работай
маленькими шагами; повторяй существующие паттерны; перед «готово» прогони
`tsc --noEmit` и `eslint` по изменённым файлам (ESLint-ошибка валит прод-сборку);
обнови README.md и PROJECT_HANDOFF.md; не пушь в main мусорные коммиты (каждый
push = деплой с даунтаймом). Если чего-то не знаешь — спроси, не гадай.

Задача: <опиши задачу>
```

> Совет: чем конкретнее задача и чем меньше её объём, тем меньше ошибок. Если
> задача крупная — попроси ИИ сначала показать план, а потом реализовать по шагам.
