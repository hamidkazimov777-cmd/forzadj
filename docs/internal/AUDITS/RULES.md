# RULES.md — Правила проведения аудитов ForzaDJ

> Обязательные правила для каждого этапа аудита. Изменяются только по явному решению владельца проекта.

---

## 1. Порядок начала работы

Каждый новый этап аудита начинается строго в таком порядке:

1. Прочитать `PROJECT_HANDOFF.md` (корень проекта) — актуальное состояние репозитория.
2. Прочитать `AUDITS/HANDOFF_AUDITS.md` — статус аудитов, что проверено, что следующее.
3. Прочитать документ текущего раздела (например `05_API.md`).
4. Только после этого открывать файлы проекта, реально нужные для проверки.

## 2. Ограничение области

- Анализировать только одну область проекта за один этап.
- Не читать весь репозиторий, не открывать файлы «про запас».
- Экономить контекст и токены; после этапа останавливаться.

## 3. Разделение тем

- Каждый файл посвящён только своей теме. Темы не смешиваются.
- `04_DATABASE.md` не содержит замечаний по UI; `02_SECURITY.md` — рекомендаций по производительности и т.д.

## 4. Формат замечания

Каждое замечание содержит:

- **ID:** префикс раздела + номер (например `SEC-001`, `API-003`). Нумерация сквозная внутри раздела, ID не переиспользуются.
- **Статус:**
  - 🔴 Требует исправления
  - 🟡 Можно улучшить
  - 🟢 Уже соответствует Best Practices
- **Приоритет:** Critical | High | Medium | Low
- **Описание** проблемы/нахождения.
- **Почему это важно.**
- **Предлагаемое решение.**
- **Файлы:** список относящихся файлов.
- **История:** даты появления и смены статуса.

## 5. Предотвращение дублирования

Перед созданием любого замечания обязательно проверить:

- нет ли его уже в другом разделе AUDITS;
- нет ли его в `FIXED_ISSUES.md`;
- нет ли его в `DECISIONS.md` (возможная «проблема» — принятое решение, тогда замечание не создаётся либо формулируется как предложение пересмотреть ADR);
- нет ли его в `CHANGELOG.md` (уже зафиксировано/закрыто на ранних этапах).

Запрещается создавать дубликаты. Если запись уже существует — не создавать новую, а обновить существующую (уточнить описание, добавить файлы, сменить статус).

## 6. Правила обновления

- Никогда не переписывать документы полностью.
- Никогда не удалять старые выводы и записи.
- Только: дополнять, уточнять, менять статусы.
- Исправленные проблемы переносятся в `FIXED_ISSUES.md` (в разделе меняется статус на «Исправлено» со ссылкой на перенос).
- Подробные отчёты каждого прохода сохраняются в `history/<дата>-<раздел>-pass-<N>.md`.
- Основные документы хранят только актуальную информацию; подробности — в `history/`.

## 7. Обязательные обновления после каждого этапа

После каждого прохода обновляются:

1. Документ раздела (замечания, статусы, дата последней проверки).
2. `HANDOFF_AUDITS.md` — статус раздела, сводка замечаний, история.
3. `CHANGELOG.md` — запись об этапе.
4. `TODO.md` — актуальная очередь следующих аудитов.
5. `00_INDEX.md` — даты последнего изменения документов.
6. `history/` — подробный отчёт прохода.
7. `FIXED_ISSUES.md` — если что-то отмечено исправленным.
